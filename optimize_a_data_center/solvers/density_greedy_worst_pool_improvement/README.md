> **Greedy by capacity per slot, worst-pool assignment, random pool swaps**
>
> Source: https://github.com/stoman/HashCode2017Warmup (`datacenter/`)
>
> Method overview:
> 1. Placement: takes the servers by capacity per slot and puts each in the row with the least capacity so far, in the first gap that fits.
> 2. Pools: gives the highest-capacity free server to the pool with the lowest guaranteed capacity, from the rows where that pool is weakest. The modes differ in how many rows count: `full-1`, `full-1-2`, `full-2-3`, `full-3-4`.
> 3. `mockplacement` uses a simpler placement with the same pool step.
> 4. Improvement: swaps random servers between the worst and the best pool, and undoes a swap that lowers the score.
>
> In our runs: 398 best, with mode `full-2-3` (mean 397.8) ([scores](../../output/density_greedy_worst_pool_improvement/scores.md)).

# Hash Code 2017 Warmup

This is our entry for the warm up round of Google Hash Code 2017 which is located in the directory `pizza`. We also solved many other problems from past contests that are contained in the respective directories.

# Technical Data

Almost all code is written in C++. You can run the code by simply starting `make all`. Output data can be generated using `make data` while visualizations can be generated by `make visualizations`. More commands can be found in the `Makefile` of each directory.

Most code is written during the 4 hours of the contest and therefore not optimized.
